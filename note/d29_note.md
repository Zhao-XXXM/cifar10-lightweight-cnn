# Day29：混淆矩阵与分类错误分析
- Day28 主要比较不同宽度模型的总体准确率、参数量和训练成本
- 但一个总 Val Acc 不能告诉我们模型具体错在哪些类别
- Day29 开始进行分类错误分析：统计每类准确率、绘制混淆矩阵、找出最常见的类别混淆，并可视化高置信度错误样本
- 这一步的目标是从“模型表现是多少”进一步走向“模型为什么会这样表现”

# 今天的实验对象
- 默认分析 Day28 的 `width_mult=1.0` 模型
- 选择它的原因是：它在当前实验中处于准确率和资源成本之间较均衡的位置
- 模型权重：`checkpoints\day28_width_models\width_1_0\best.pth`
- 也可以通过命令行把 `0.5`、`1.0`、`1.5` 三个模型一起分析
- 三个模型必须使用相同测试集和相同类别顺序，才能进行公平比较

# 混淆矩阵是什么
- 混淆矩阵是一个 `10 * 10` 的表格，用来记录真实类别和预测类别的对应关系
- 第 `i` 行表示真实类别为 `i` 的样本
- 第 `j` 列表示模型预测为 `j` 的样本
- 对角线元素表示预测正确的样本数量
- 非对角线元素表示分类错误，例如第 `cat` 行第 `dog` 列表示真实是猫、却被预测成狗
- 本项目使用“行表示真实类别、列表示预测类别”的约定，阅读图像时不要把两个方向弄反

# 每类准确率的计算
- 对于类别 `i`，该类准确率为：`正确预测为 i 的样本数 / 真实属于 i 的样本总数`
- 用混淆矩阵表示就是：`C[i, i] / sum(C[i, :])`
- CIFAR-10 测试集每类通常有 1,000 张图，因此可以直接比较不同类别的识别难度
- 总准确率是所有类别正确样本数之和除以总样本数
- 当每个类别样本数相同，总准确率也等于各类别准确率的平均值

# 为什么要分析类别差异
- CIFAR-10 的类别视觉难度并不相同
- `airplane`、`ship` 等类别的整体轮廓可能比较明显
- `cat`、`dog`、`deer`、`horse` 等类别在 32 * 32 的低分辨率图像中更容易混淆
- 如果某一类准确率明显偏低，说明模型可能没有学到该类别足够稳定的判别特征
- 错误分析可以帮助我们提出下一步改进假设，例如增加数据增强、调整模型容量或改善训练策略

# 从概率角度理解错误
- 模型最后输出的是 10 个 logits，而不是直接输出类别名称
- 经过 Softmax 后得到每个类别的预测概率
- `argmax` 选择概率最大的类别作为 Top-1 预测
- 高置信度错误表示模型对错误类别也很确信，这类样本比低置信度错误更值得优先检查
- 但置信度不等于真实概率，Softmax 分数高不代表模型一定校准良好

# 代码拆解
- `build_test_loader`：加载与训练时一致的归一化测试集
- `collect_predictions`：执行推理，累计混淆矩阵并保存高置信度错误样本
- `confusion[true_label, predicted_label] += 1`：把一次预测写入矩阵对应位置
- `save_class_metrics`：计算并保存每类样本数、正确数和类别准确率
- `save_confused_pairs`：去掉对角线后，按照错误次数从高到低排列类别混淆对
- `save_confusion_matrix`：把按行归一化后的矩阵绘制为热力图
- `save_error_grid`：反归一化图像，绘制真实标签、预测标签和预测置信度
- `summary.json`：保存总体准确率、最差类别和最常见混淆对

# 运行方式
- 先做语法检查：`venv\Scripts\python.exe -m py_compile notecode\d29_error_analysis.py`
- 默认分析 `width_mult=1.0`：`venv\Scripts\python.exe notecode\d29_error_analysis.py`
- 分析三个宽度：`venv\Scripts\python.exe notecode\d29_error_analysis.py --widths 0.5,1.0,1.5`
- 如果电脑内存紧张，可以减小批大小：`venv\Scripts\python.exe notecode\d29_error_analysis.py --batch-size 64`
- 限制错误样本图数量：`venv\Scripts\python.exe notecode\d29_error_analysis.py --max-errors 12`

# 输出文件
- `class_metrics.csv`：每个类别的样本数、正确数和准确率
- `confused_pairs.csv`：所有非对角线混淆对及其出现次数
- `confusion_matrix.png`：按真实类别归一化的混淆矩阵热力图
- `error_examples.png`：模型高置信度错误样本图
- `summary.json`：本次诊断的总体摘要
- 输出目录：`checkpoints\day29_error_analysis\width_x_x\`

# 实验结果记录
- `width_mult=0.5`：总体准确率为 68.62%，最差类别为 `cat`，准确率为 44.80%；最高类别为 `truck`，准确率为 86.00%
- `width_mult=1.0`：总体准确率为 74.88%，最差类别为 `cat`，准确率为 55.00%；最高类别为 `automobile`，准确率为 90.50%
- `width_mult=1.5`：总体准确率为 75.52%，最差类别为 `cat`，准确率为 59.30%；最高类别为 `ship`，准确率为 86.10%
- 三个模型中 `cat` 都是最难识别的类别，说明该问题不是某一个宽度模型的偶然现象，可能与 CIFAR-10 图像分辨率低、猫的外观变化大以及和其他动物类别相似有关
- `cat` 类准确率从 `0.5` 到 `1.5` 提升 14.50 个百分点，`bird` 类提升 15.30 个百分点，说明增加通道容量对部分细粒度或外观变化大的类别更有帮助
- `width_mult=1.5` 并没有让每个类别都变好：相对 `1.0`，`automobile` 从 90.50% 降到 84.80%，`frog` 从 84.50% 降到 75.50%，因此不能把总准确率的小幅提升解释成所有类别都得到改善
- `width_mult=0.5` 最常见的错误是 `cat -> dog`，共 180 次；同时 `dog -> cat` 有 160 次，说明猫狗之间存在明显的双向混淆
- `width_mult=1.0` 最常见的错误是 `dog -> cat`，共 161 次，其次是 `truck -> automobile`，共 150 次，第三是 `cat -> dog`，共 126 次
- `width_mult=1.5` 最常见的错误是 `dog -> cat`，共 177 次，其次是 `cat -> dog`，共 136 次；猫狗混淆仍然是最稳定的主要错误来源
- 注意区分 `cat -> dog` 和 `dog -> cat`，它们是两个不同的混淆方向；混淆矩阵中行是真实类别，列是预测类别
- 从 `error_examples.png` 可以看到，部分高置信度错误来自车辆外观相似、动物姿态变化和 32 * 32 图像细节不足，说明错误不仅是随机噪声
- 本次分析支持这样的阶段性判断：增加宽度可以改善部分困难类别，但总体准确率提升有限，且类别收益不均衡；后续仍需结合数据增强和多随机种子实验验证
