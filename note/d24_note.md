# Global Average Pooling
- 今天的目标是解决 Day20 发现的问题：LightVGG-Slim 的特征提取部分已经很轻，但分类头仍然参数很多
- Global Average Pooling 简称 GAP，是现代 CNN 中常见的轻量分类头设计

# Flatten 分类头的问题
- Day20 的 LightVGG-Slim 在卷积后得到 `128x4x4` 特征图
- Flatten 后会变成 `128 * 4 * 4 = 2048` 维向量
- 第一层全连接为 `Linear(2048, 256)`，参数量为 `2048 * 256 + 256 = 524544`
- 这导致模型虽然卷积部分变轻，但分类头仍然是参数大户

# GAP 的核心思想
- GAP 对每个通道的整张特征图求平均值
- 输入是 `128x4x4`，输出变成 `128x1x1`
- 每个通道最终只保留一个全局响应值
- 这相当于把空间位置上的信息压缩成通道级语义描述

# AdaptiveAvgPool2d
- `nn.AdaptiveAvgPool2d((1, 1))` 可以把任意空间尺寸的特征图压缩到 `1x1`
- 它不需要手动指定 kernel size
- 对 CIFAR-10 来说，`128x4x4 -> 128x1x1`
- 后面再用 `torch.flatten(x, 1)` 得到 `128` 维向量

# GAP 分类头
- 原分类头：`Flatten -> Linear(2048, 256) -> ReLU -> Dropout -> Linear(256, 10)`
- GAP 分类头：`AdaptiveAvgPool2d(1) -> Flatten -> Linear(128, 10)`
- 新分类头参数量为：`128 * 10 + 10 = 1290`
- 和原来的 527114 个分类头参数相比，减少非常明显

# GAP 的优点
- 显著减少全连接层参数量
- 降低过拟合风险
- 让分类结果更直接依赖每个通道的整体响应
- 支持不同空间尺寸的输入特征图，结构更灵活

# GAP 的潜在代价
- GAP 会丢失一部分空间位置信息
- 如果任务非常依赖目标位置，过早使用 GAP 可能影响表达能力
- CIFAR-10 是图像级分类任务，更关注整张图属于哪一类，因此 GAP 通常比较合适
