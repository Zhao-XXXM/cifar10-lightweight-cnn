# Width Multiplier
- Day27 学习 MobileNet 中常见的 Width Multiplier，也就是通道宽度缩放
- 它通过统一放大或缩小每一层通道数，控制模型容量和参数量
- 今天只做结构验证和参数统计，不训练模型

# 为什么通道数重要
- 卷积层参数量与输入通道数和输出通道数都有关
- 普通卷积参数量约为：`Cin * Cout * K * K`
- 深度可分离卷积参数量约为：`Cin * K * K + Cin * Cout`
- 即使使用轻量卷积，Pointwise 1 * 1 卷积仍然和 `Cin * Cout` 有关

# Width Multiplier 的定义
- Width Multiplier 记作 `alpha`
- 原始通道数为 `[32, 64, 128]`
- 当 `alpha = 0.5` 时，通道数变为 `[16, 32, 64]`
- 当 `alpha = 1.0` 时，通道数保持 `[32, 64, 128]`
- 当 `alpha = 1.5` 时，通道数变为 `[48, 96, 192]`

# 参数量变化规律
- 通道数缩小会降低模型参数量和计算量
- 通道数放大会提升模型容量，但也增加参数量和计算成本
- 对包含大量 `Cin * Cout` 的结构来说，参数量通常会接近随宽度平方增长
- 但第一层输入通道固定为 3，分类头输出类别固定为 10，所以实际增长不会完全等于平方关系

# 为什么要做宽度缩放实验
- 它可以系统地观察模型容量与准确率之间的关系
- 只改宽度，不改网络深度和训练策略，变量更清晰
- 后续 Day28 会训练不同宽度模型，比较参数量、准确率和训练时间

# 通道数取整
- 代码中使用 `int(base_channels * width_mult)` 计算缩放后的通道数
- 同时用 `max(1, value)` 保证通道数至少为 1
- 在真实工程中，通道数常会取整到 8 的倍数，以适配硬件加速
- 当前学习项目先保持简单，重点理解缩放思想

# 运行结果记录
- `width_mult=0.5`：通道数为 `[16, 32, 64]`，参数量为 10,875
- `width_mult=1.0`：通道数为 `[32, 64, 128]`，参数量为 37,579
- `width_mult=1.5`：通道数为 `[48, 96, 192]`，参数量为 80,155
- 相对 `width_mult=1.0`，0.5 宽度参数量约为 0.289 倍，1.5 宽度参数量约为 2.133 倍
- 它们没有严格等于 0.25 倍和 2.25 倍，因为第一层输入通道固定为 3，最后分类输出固定为 10
