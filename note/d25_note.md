# 训练 LightVGG-Slim-GAP
- Day25 开始训练 Day24 的 `LightVGGSlimGAP`
- 核心问题：参数量从 563,403 降到 37,579 后，验证准确率会下降多少
- 这一步用于判断 GAP 分类头是否值得保留

# 公平对照
- 与 Day21 的 LightVGG-Slim 使用相同训练配置
- 数据集：CIFAR-10
- Batch Size：64
- 优化器：Adam
- 学习率：0.001
- Epoch：10
- 随机种子：42
- 暂时不加入数据增强、Weight Decay 或 Cosine Scheduler

# 为什么先不加训练技巧
- Day25 的主要变量是分类头结构
- 如果同时加入数据增强或学习率调度，就无法判断性能变化到底来自 GAP，还是来自训练策略
- 先做干净对照，再做强化训练，是更规范的实验顺序

# 评价指标
- 参数量：衡量模型复杂度
- 最佳 Val Acc：衡量分类性能
- 训练耗时：衡量训练成本
- checkpoint 大小：衡量模型存储成本
- 后续 Day26 会把这些指标汇总到同一张表

# 可能出现的结果
- 如果准确率接近 Day21，说明 GAP 在大幅压缩参数的同时保留了主要表达能力
- 如果准确率明显下降，说明原来的大分类头确实提供了额外拟合能力
- 如果训练集和验证集准确率都偏低，说明模型容量可能不足
- 如果训练集准确率高而验证集低，说明仍然存在过拟合

# 当前实验预期
- 参数量会显著降低
- 训练速度可能略有提升，但 CPU 上差异不一定特别明显
- 准确率可能低于 LightVGG-Slim，因为分类头表达能力被大幅压缩
- 这正是轻量化项目需要分析的“参数量-准确率权衡”

# 运行方式
- 冒烟测试：`venv\Scripts\python.exe notecode\d25_train_light_gap.py --epochs 1`
- 正式训练：`venv\Scripts\python.exe notecode\d25_train_light_gap.py --epochs 10`
