# 训练不同宽度的轻量模型
- Day28 开始把 Day27 的 `WidthLightVGGSlimGAP` 真正放到 CIFAR-10 上训练
- 今天的核心问题是：通道数变小或变大后，准确率、参数量、模型大小和训练时间会怎样变化
- 这一步不是为了立刻追求最高准确率，而是建立轻量化项目里最重要的“容量-精度-成本”对照实验

# 今天的实验变量
- 唯一主要变量是 `width_mult`
- 训练三个模型：`0.5`、`1.0`、`1.5`
- `width_mult=0.5`：通道更少，模型容量更小，参数量更低
- `width_mult=1.0`：保持 Day24 的 GAP 版本宽度
- `width_mult=1.5`：通道更多，模型容量更大，参数量更高

# 为什么要保持训练配置一致
- 对照实验必须尽量只改变一个变量
- 如果同时改变数据增强、学习率、优化器或 epoch，就无法判断性能变化到底来自宽度，还是来自训练策略
- 所以 Day28 继续沿用 Day25 的干净训练配置
- 数据集：CIFAR-10
- Batch Size：64
- 优化器：Adam
- 学习率：0.001
- Epoch：10
- 随机种子：42
- 暂时不加入数据增强、Weight Decay 和 Cosine Scheduler

# 宽度倍率的数学直觉
- 普通卷积参数量约为 `Cin * Cout * K * K`
- 深度可分离卷积参数量约为 `Cin * K * K + Cin * Cout`
- 在深度可分离卷积中，`1 * 1` Pointwise Conv 仍然和 `Cin * Cout` 有关
- 当宽度倍率 `alpha` 同时缩放输入通道和输出通道时，主要卷积层的参数量通常接近按 `alpha^2` 变化
- 但第一层输入通道固定为 3，最后分类输出固定为 10，所以总参数量不会严格等于 `alpha^2` 倍

# 模型容量与欠拟合
- 通道数可以理解为每层能学习多少组特征
- 通道太少时，模型表达能力可能不足，训练集和验证集准确率都会偏低，这通常叫欠拟合
- 通道更多时，模型有更强表达能力，训练集准确率可能提升
- 但模型变大不一定带来验证准确率提升，因为验证集表现还会受训练策略、数据量和泛化能力影响

# 今天要记录的指标
- 参数量：衡量模型可训练参数规模
- 最佳 Val Acc：衡量分类性能
- 最佳 Epoch：观察模型什么时候达到最好验证效果
- 最后一轮 Val Acc：观察训练结束时是否回落
- checkpoint 大小：衡量模型存储成本
- 训练时间：衡量训练成本
- Acc/百万参数：粗略观察每百万参数换来多少验证准确率

# 运行方式
- 冒烟测试：`venv\Scripts\python.exe notecode\d28_train_width_models.py --epochs 1 --widths 0.5`
- 正式训练：`venv\Scripts\python.exe notecode\d28_train_width_models.py --epochs 10`
- 汇总结果会保存到：`checkpoints\day28_width_models\summary.csv`
- 每个宽度的最优权重会分别保存到：`checkpoints\day28_width_models\width_x_x\best.pth`

# 代码拆解
- `parse_widths`：把命令行输入的 `0.5,1.0,1.5` 转成浮点数列表
- `width_to_name`：把宽度倍率转成目录名，例如 `0.5` 变成 `width_0_5`
- `build_loaders`：构建 CIFAR-10 的训练集和测试集 DataLoader
- `run_width_experiment`：负责训练某一个宽度倍率的模型
- `history`：逐轮记录 Train Loss、Train Acc、Val Loss、Val Acc
- `best.pth`：只保存验证准确率最高的那一轮权重
- `summary.csv`：把所有宽度模型的结果放到同一张表里，方便后续画图和写 README

# 结果分析时不要犯的错误
- 不能只看准确率，因为轻量化项目同时关心模型体积和参数量
- 不能说宽度越大一定越好，因为小数据集和短训练轮数下，大模型未必充分训练
- 不能把一次实验结果当成绝对结论，后续还需要多随机种子验证
- 不能把参数量减少比例直接等同于推理速度提升比例，因为真实速度还受硬件、内存访问和算子实现影响

# 运行结果记录
- 冒烟测试：`width_mult=0.5`，`epochs=1`，参数量为 10,875，Val Acc 为 46.98%，checkpoint 大小约 0.06 MB，训练耗时约 54.45 秒
- 注意：冒烟测试只用于检查代码链路是否正常，不能作为正式实验结论
- `width_mult=0.5`：通道数为 `[16, 32, 64]`，参数量为 10,875，最佳 Val Acc 为 68.62%，最佳 Epoch 为 10，最终 Val Acc 为 68.62%，checkpoint 大小约 0.065 MB，训练耗时约 615.27 秒
- `width_mult=1.0`：通道数为 `[32, 64, 128]`，参数量为 37,579，最佳 Val Acc 为 74.88%，最佳 Epoch 为 10，最终 Val Acc 为 74.88%，checkpoint 大小约 0.170 MB，训练耗时约 978.92 秒
- `width_mult=1.5`：通道数为 `[48, 96, 192]`，参数量为 80,155，最佳 Val Acc 为 75.52%，最佳 Epoch 为 10，最终 Val Acc 为 75.52%，checkpoint 大小约 0.335 MB，训练耗时约 1882.88 秒
- 三个模型的 Acc/百万参数分别约为 6309.89、1992.60 和 942.17；该指标说明小模型的参数利用率更高，但不能单独代表模型综合性能

# 宽度-准确率-成本分析
- 相比 `width_mult=1.0`，`width_mult=0.5` 的参数量减少约 71.06%，checkpoint 减小约 61.73%，训练时间减少约 37.15%，但 Val Acc 下降 6.26 个百分点
- `width_mult=0.5` 第 10 轮 Train Acc 为 69.85%，Val Acc 为 68.62%，二者都明显低于更宽模型，说明当前结果具有模型容量不足和欠拟合的倾向
- 相比 `width_mult=1.0`，`width_mult=1.5` 的参数量增加约 113.30%，checkpoint 增大约 97.40%，训练时间增加约 92.34%，但 Val Acc 只提升 0.64 个百分点
- 因此从 `1.0` 扩宽到 `1.5` 已经出现明显的边际收益递减：付出了接近两倍的存储和训练成本，却只换来很小的准确率提升
- `width_mult=1.5` 第 10 轮 Train Acc 为 83.80%，Val Acc 为 75.52%，相差约 8.28 个百分点；模型变宽后拟合训练集的能力增强，同时过拟合倾向也更明显
- 三个模型的最佳 Val Acc 都出现在第 10 轮，说明在当前 10 Epoch 预算下仍可能没有完全收敛，不能据此断言更长训练后模型排序一定不变
- 在本次单随机种子、10 Epoch 实验中，`width_mult=1.5` 的绝对准确率最高，`width_mult=0.5` 的资源成本最低，`width_mult=1.0` 在准确率与成本之间更均衡
- 当前结论只适用于本次实验设置，后续还需要用多随机种子、FLOPs 和真实推理时间进一步验证
